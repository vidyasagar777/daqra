Disaster model

DVS is a normalized vulnerability score in [0, 1]. Each link fails independently with probability p = 1 − exp(−I × DVS), so I = 0 is the no-disaster baseline with p = 0. This is a user-defined model, not a validated hazard model. Nodes are assumed not to fail in the simulation. Model and assumptions

Version 0.3 engineering planning model. Results are not experimentally validated unless the Calibration tab shows agreement with your measurements. Planning status is not a cryptographic security claim.
TopicAssumption or limitation
ProtocolsBB84: asymptotic decoy-state analysis with infinite decoys (Y1 and e1 from the channel model). COW: heuristic estimate from data-line detection and monitoring-line visibility, with no proven security bound. MDI-QKD: two explicit arms with separate transmittances, Bell-state measurement, leading-order yields and one misalignment error term, asymptotic decoy-state form; check the yield expressions against your own derivation. E91 was removed because no defensible engine exists here.
SourcePoissonian weak coherent pulses with mean photon number μ and perfect phase randomization.
Key-rate namingResults are estimated secret key rates under the stated assumptions, not certified secure key rates. No security parameter ε is applied.
Wavelength gridCustom and Experimental modes make no standards claim. ITU-T DWDM mode checks the spacing against multiples of the 12.5 GHz grid of G.694.1. CWDM mode checks multiples of 20 nm.
Survivability metricProposed metric, not an established standard. Path availability A is the product of (1 − p) over its links. Proposed Protected Path Survivability (PPS) = 1 − (1 − A_primary)(1 − A_backup), exact for link-disjoint paths under independent failures. The Monte Carlo run uses a seeded generator and a Wilson 95 % confidence interval.
Validation protocolCalibration uses a deterministic interleaved split (default 70 % calibration, 30 % held out). Fitted parameters are detector efficiency, visibility and, for rows with a launch power, the peak Raman coefficient. Reported validation error uses held-out rows only. An independent final test set is still needed for publication.
Hardware integrationPlanned. No device communication exists. The dashboard key pool and QBER trend are simulated.
FiberLoss equals dB/km times length. No dispersion, polarization drift, splice or connector loss.
DetectorEfficiency, dark-count probability per gate, afterpulse probability (first-order background of afterpulse × click probability), dead time (rate factor 1 / (1 + click probability × dead gates)) and timing jitter (efficiency factor erf(gate / (2√2 σ))). First-order approximations, not a detector simulation. No detector side channels.
QBERDark counts add errors with probability 1/2. Misalignment error e_d = (1 − visibility) / 2 applies to signal events.
Estimated secret key rateR = q × clock × [Q1 (1 − h(e1)) − Q f_EC h(E)] with q = 1/2. Asymptotic: no finite-key bound, no ε, no authentication cost, no side-channel or implementation analysis.
Authentication, key managementNot modelled. Trusted-node relaying is assumed. Key consumption is not simulated and the dashboard key pool is illustrative.
WDMNoise = ρ(Δν) × filter bandwidth × launch power × effective length (forward L·e^(−αL), backward (1 − e^(−2αL))/(2α)) plus classical leakage P·e^(−αL)·10^(−isolation/10), converted to counts per gate. ρ(Δν) = ρ_peak × min(Δν / 13 THz, 1) × a Bose factor relative to the 13 THz Stokes peak (Stokes when the classical channel is at the shorter wavelength); held flat beyond 13 THz, an approximation. ρ_peak is a placeholder until calibrated. No four-wave mixing, Brillouin scattering or filter-shape model.
RoutingDijkstra with per-hop cost a·QBER' + b·DVS' + c·(1/SKR)' + d·latency', each min-max normalized over the active links. Default weights are 1: they are not Pareto-derived or sensitivity-tested. Cost sums over hops, so it also favors fewer hops. Path QBER is the worst hop and path SKR the weakest hop. Latency is 5 µs/km plus 0.1 ms per hop. The backup is link-disjoint by default or node-disjoint when selected. SRLG-disjoint protection and Pareto weight generation are not implemented.
Availability and disasterDVS is a normalized vulnerability score, not a probability. Failure probability is p = 1 − exp(−I × DVS) for disaster intensity I. Links fail independently and nodes do not fail in the simulation. No spatial correlation.
Planning statusAcceptable means a route exists with QBER at most 5 % and positive key rate under this model.
Not in this pageFinite-key analysis, Pareto derivation of the routing weights, hardware APIs, user accounts and roles, database, REST API, PDF and Excel export. The production architecture is React with TypeScript, FastAPI, NetworkX and NumPy engines, PostgreSQL and Docker. This page serves as the UI specification.
